# Analyst hypotheses for new integrated churn measurements

**Owner:** Aditya (Analyst)  
**Drafted:** 16 November 2026, after Mayank's reference results were published. These are **not** preregistered predictions for those earlier experiments. Record commit hash before new runs.

## What is being predicted (not retroactively fitted)

1. An ordinary Hibbard BST has worst-case height O(n); sorted insertion is a worst-case example, not a proof of the long-run random-churn law. Under shallow-targeted two-child deletion with always-successor replacement, average depth may grow markedly.
2. Scapegoat search height and amortized update cost are O(log n) for fixed alpha in (1/2, 1), even though one rebuild may cost O(n).
3. For fixed size n >= 1000 and alpha=0.7, the sequence n -> n-1 -> n cannot trigger a deletion-driven whole-tree rebuild when the stored maximum population q equals n, because n-1 >= 0.7n.
4. Cost model: total time ≈ c_path*(search-path work) + c_rebuild*(nodes rebuilt) + c_misc*(operation count). Coefficients are machine-dependent and not known in advance. Event *frequency* alone is not a runtime predictor because rebuild sizes vary.
5. A local rebuild of s nodes costs Theta(s). A predicted *numeric* rebuild rate does not follow from O(log n) amortized cost. We will report local rebuilds/pair and rebuilt nodes/pair rather than inventing a universal constant rate.

## Planned measurement

- Use identical seeded initial insertion order and identical pair traces across the four strategies for each (workload,n,trial).
- Each pair deletes a present key then inserts an absent key; population remains exactly n at pair boundaries.
- Four workloads: random, exact, shallow_exact and shallow_fresh, generated by `adversary/`.
- Standard n=1000,2000,4000, >=n*n pairs, >=5 trials, snapshots at fixed pair intervals.
- Structure timing excludes generator work, initial construction, consistency audits and scans of whole-tree depths.
- Report final average depth, trajectory, timing in nanoseconds per single tree operation, rebuild count, rebuilt nodes, rotations, trial mean and sample SD.
- CPU/compiler/OS/source commit and limitations must accompany timing. Hardware cache claims require profiler output; otherwise do not make them.

## Interpretation limits

The repository's `adversary/RESULTS.md` measured a **separate reference project**, partly different from current `main`. Those values provide a comparison point, not proof that this Analyst executable on current `main` produces identical results. No experiments reported in this document have been run yet.

For ordinary random churn, the D6 random-insertion reference model predicts local events per pair of 2.73%, 2.42% and 2.14% at the three ascending sizes. See bench/predict_rate.py and the D6 addendum.
